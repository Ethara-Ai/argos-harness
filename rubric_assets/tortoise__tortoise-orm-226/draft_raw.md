# Canonical Solve Notes

## 1. Problem
The stated PR is a docs-only issue: the "Aggregation" documentation anchor/section referenced a source file (`examples/aggregation.py`) that had been renamed to `examples/functions.py`, so the documented aggregation/functions example rendered broken or pointed at a stale target. The actual merged fix goes further and also lands the "add type hints for relation managers" feature request bundled into the same release: `ManyToManyField` is turned into a factory function returning a properly generically-typed `ManyToManyRelation`, `RelationQueryContainer`/`ManyToManyRelationManager` are renamed to `ReverseRelation`/`ManyToManyRelation` (now `Generic[MODEL]`), the old `ManyToManyField` class becomes `ManyToManyFieldInstance`, and all internal references, examples, and docs are updated accordingly. The root cause of the doc bug was a stale `.. literalinclude::` path/label in `docs/examples/basic.rst`; the broader change was needed because renaming/typing the relation fields required every call site (`tortoise/__init__.py`, `models.py`, `filters.py`, `query_utils.py`, `executor.py`, pylint plugin, docs, examples, test models) referencing `ManyToManyField` as a class to be updated to `ManyToManyFieldInstance`.

## 2. Load-bearing changes
- `docs/examples/basic.rst`: rename anchor `_example_aggregation` → `_example_functions`, section title "Aggregation" → "Functions", and `literalinclude` path `../../examples/aggregation.py` → `../../examples/functions.py`. This is the core fix for the reported broken doc link.
- `tortoise/fields.py`:
  - Renamed the old `ManyToManyField` class to `ManyToManyFieldInstance`.
  - Added a new `ManyToManyField(...)` function that constructs and returns a `ManyToManyFieldInstance`, annotated to return `"ManyToManyRelation"` for IDE type inference — required to satisfy the type-hinting feature request.
  - Renamed `RelationQueryContainer` → `ReverseRelation`, now `Generic[MODEL]`; renamed `ManyToManyRelationManager` → `ManyToManyRelation(ReverseRelation[MODEL])`.
  - Added `ForeignKeyRelation` and `ForeignKeyNullableRelation` type aliases for use as field annotations.
  - Added a stub `__await__` on `ForeignKeyField` so IDEs don't flag `await` on FK fields.
- `tortoise/__init__.py`, `tortoise/models.py`, `tortoise/filters.py`, `tortoise/query_utils.py`, `tortoise/backends/base/executor.py`, `tortoise/contrib/pylint/__init__.py`: every `isinstance`/type-annotation reference to `fields.ManyToManyField` (as a class) updated to `fields.ManyToManyFieldInstance`; every reference to `RelationQueryContainer`/`ManyToManyRelationManager` updated to `ReverseRelation`/`ManyToManyRelation`. These are required so the runtime type checks and pylint model-attribute injection keep working after the class rename.
- `docs/fields.rst`, `docs/query.rst`, `docs/models.rst`: updated autodoc directives to match renamed symbols (`autofunction` for `ManyToManyField`, `autodata` for the new relation type aliases, `autoclass` for `ReverseRelation`/`ManyToManyRelation`), plus a new "Improving relational type hinting" section with a worked example — supporting documentation for the type-hint feature, not required for the aggregation link fix itself.
- `examples/*.py` (`functions.py`, `relations.py`, `relations_recursive.py`, `complex_filtering.py`, `complex_prefetching.py`, `schema_create.py`, `two_databases.py`): added relation type annotations (`fields.ForeignKeyRelation[...]`, `fields.ManyToManyRelation[...]`, `fields.ReverseRelation[...]`) to model fields, demonstrating/supporting the new typing feature; refactor/illustrative only, not required for the documentation link fix.
- `docs/sphinx_autodoc_typehints.py`: fixed `get_type_hints` calls to pass `localns=` keyword and to not silently swallow all exceptions with a bare `except:` — refactor/robustness fix so Sphinx can resolve the new forward-reference type hints used in examples/models.
- `CHANGELOG.rst` and version bump in `tortoise/__init__.py` (`0.14.0` → `0.14.1`): bookkeeping, not functionally load-bearing for the fix itself.
- `Makefile` / `docs/CONTRIBUTING.rst`: unrelated maintenance change (env var passwords for DB tests, contributing docs) merged into the same release; not related to the documentation link issue.

## 3. Correct verification behavior
Because this is fundamentally a documentation fix, the correct check is to build the Sphinx docs (e.g. `cd docs && sphinx-build -b html . _build` or the project's documented doc-build command) and confirm there are no broken `literalinclude` warnings/errors, that the "Functions" section under `docs/examples/basic.rst` resolves and renders the content of `examples/functions.py`, and that no reference to `examples/aggregation.py` remains in the docs tree (`grep -r aggregation docs/`). Since the actual landed change also touches the `fields` module renames, a careful verification should additionally run the full test suite (`make test` or `pytest`) to confirm nothing broke from the `ManyToManyField`→`ManyToManyFieldInstance` rename and the `RelationQueryContainer`/`ManyToManyRelationManager` renames — in particular `tests/test_describe_model.py` (which asserts on `field_type` names/classes), `tests/testmodels.py`-based tests, and any tests exercising m2m/FK relation containers. Confirm `import tortoise` still succeeds and that `Tortoise.init_models` schema generation (which internally instantiates the m2m field via `fields.ManyToManyFieldInstance`) still works.

## 4. Traps and near-misses
- Only fixing `docs/examples/basic.rst` (the anchor/title/literalinclude) without touching `tortoise/fields.py` is actually a complete and correct fix for the literal reported issue — the broader renames are a separate bundled feature and not required to resolve the broken doc link. A reviewer should not assume the `ManyToManyField`→`ManyToManyFieldInstance` refactor is mandatory for this specific bug.
- Renaming `examples/aggregation.py` to `examples/functions.py` (file move) instead of just fixing the `.rst` reference would work only if the file didn't already exist under the new name — in this codebase `examples/functions.py` already exists as the renamed target, so recreating a duplicate `aggregation.py` or moving files is unnecessary and risks stale duplicate content.
- If the `ManyToManyField` rename is attempted, forgetting to update all `isinstance(field, fields.ManyToManyField)` call sites (in `tortoise/__init__.py`, `filters.py`, `query_utils.py`, `models.py`, `executor.py`, pylint plugin) breaks m2m filtering, schema description, and join generation, since `ManyToManyField` after the change is a plain function and `isinstance` checks against it will raise `TypeError`.
- Leaving `RelationQueryContainer`/`ManyToManyRelationManager` as aliases instead of true renames (e.g. `RelationQueryContainer = ReverseRelation`) would satisfy some existing test assertions on class identity but not the `test_describe_model.py` string-based assertions expecting the literal `"ManyToManyFieldInstance"` name.
- Fixing only the anchor label (`_example_aggregation` → `_example_functions`) but leaving the `literalinclude` path pointed at the old `examples/aggregation.py` (or vice versa) would leave the Sphinx build failing/broken since that source file no longer exists under the old name.
- Bumping the changelog/version without actually changing the doc source produces no functional fix and leaves the broken link live.
